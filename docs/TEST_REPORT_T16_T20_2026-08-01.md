## 2. T16 审核发现与修复

原 T16 交付不能判定为任务通过，原因如下：

- Mock SDK 的标签条件恒等于首标签，实际只产生 `A`，无法验证 A→B→C；已改为确定性循环。
- Node 专项读取器每阶段固定等待完整超时，测试约 102 秒；已改为持久事件收集器，约 3 秒结束。
- 原测试只覆盖 Runner/Frame，不覆盖 Router→Scene Entry→Sequence→outcome；已加入完整 Mock 闭环、NG、scene disable 和 SDK 不停止断言。
- 人工 `pause_source` 会被低水位逻辑自动恢复；已区分人工暂停与背压暂停，并验证另一 source 不受影响。
- Python 验证器会丢弃同批非目标事件、不能按 request_id 匹配，且原生 GBK stderr 会使读取线程崩溃；均已修复。
- 外部 working directory 下 `python -m python_runtime...` 缺项目路径；验证器现显式注入 `PYTHONPATH`。

真实执行附件：

- `tmp/t16-real-audit-v3.json`
- `tmp/t16-mock-final.json`

真实 Pipeline YAML 已成功解析为 group 1 / source 1 / model 1；Runner 发出 `runtime_starting` 后 SDK 模块加载失败，未到 `runtime_ready`。清理后孤儿扫描为 0。

## 3. T17 数据和副作用合同

目标表为 `icamera_data.workflow_result_event`，DDL 位于 `node-red-contrib-aiban-workflow/sql/schema.sql`。

关键约束：

- `result_event_id` 为 UNIQUE 业务幂等键。
- `workflow_id`、`scene_id`、`cycle_id`、`result_status` 和 `image_path` 均为可查询列。
- OK/NG/TIMEOUT/INTERRUPTED 原样入库；不再把 TIMEOUT/INTERRUPTED 压成旧表的 NG 字符串。
- MySQL 不可用时指数退避，最终失败写 `db-failed.jsonl`；`replayFailureFile()` 可重放并归档原失败文件。
- `close()` 会停止接收新任务并排空已接收队列。
- `aiban-api-output` 只消费标准 terminal result；本地 SQLite ledger 和 HTTP `Idempotency-Key` 共同防止重复通知。

真实 MySQL 验收命令和断库步骤见 `docs/OPERATIONS.md`。

## 4. T18 稳定性

短时自检命令：

```powershell
node tools/run_stability_test.js --mock `
  --duration-seconds 120 `
  --output tmp/t18-smoke.json
```

正式 24 小时命令：

```powershell
node tools/run_stability_test.js `
  --duration-hours 24 `
  --python D:/my_env/python.exe `
  --sdk-home D:/product/AiBanWorkSpace `
  --pipeline-config D:/product/AiBanWorkSpace/abvideo/main-flow.yaml `
  --working-directory D:/product/AiBanWorkSpace `
  --output outputs/t18-24h.json
```

Harness 自动判定：帧存在、event_seq 单调、queue drop/overflow、重复 terminal/副作用、旧 scene 新周期和正常停止。Node-RED Deploy、真实 MySQL 断开恢复、scene 快切及截图超时必须在现场步骤中附 operation_id、result_event_id 和日志。
